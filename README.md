# Kurage 地震ハザードマップ（名古屋版） (kjishin)

住所または**地番**を入れると、南海トラフ地震（最大クラス）で想定される
**震度**と**液状化の危険度**を返す。名古屋市の公開データ（CC BY 4.0）にもとづく。

- 公開: https://kurage.exbridge.jp/kjishin.php/
- バックエンド: `127.0.0.1:18353`（user unit `kjishin.service`）
- 収録: **126,385メッシュ（約50m）** ＋ **982,180筆**（地番参考図）
- 対象は**名古屋市内のみ**。市外は「範囲外」と返す

## 活断層マップ(kfault)との違い

| | |
|---|---|
| kfault | 活断層の線の**直上か、何メートル離れているか**。**震源**の話 |
| **kjishin** | その場所が**何震度になり、液状化するか**。**揺れの結果**の話 |

市内のほぼ全域が震度6弱以上（6弱 51.5%・6強 46.4%・震度7 1.3%）。

## 地番で判定精度を上げている

Kurageの防災GISはどれも「住所は町丁目の代表点だから地番で確認してください」と断ってきた。
名古屋市は**地番参考図をCC BY 4.0で公開している**ので、市内に限っては**筆の形**で判定できる。

- 地番を入れれば、その筆にかかるメッシュを全部見て、**計測震度の幅**（例: 6.06〜6.18）で返す
- 住所を入れた場合も、代表点が筆に乗っていればその筆で判定する
- 液状化は**いちばん危険な側**を代表にする（敷地の一部でも危険が高いなら伝えないと意味がない）

**座標系の罠**: 地番参考図は `.prj` が入っておらず、座標は**平面直角座標系（メートル）**。
愛知県は**第VII系（EPSG:6675）**。実測で確認した（栄三丁目の筆が 35.16192N/136.90463E＝名古屋中心部。
第6系だと京都、第8系だと静岡に飛ぶ）。取り込み時に EPSG:6668 へ変換している。

## 液状化の「判定対象外」（推測で埋めていない）

PL値に **-1.0（4,930）と -6.6（30,665）** の2種類の負の値がある。どちらもPL値と沈下量が
同じ値＝計算結果ではなく欠測コード。**この2つの定義は配布元にも市の公開資料にも無い。**

分布を実測した: -6.6の94.2%・-1.0の87.9%が市の**東側**（熱田台地・東部丘陵）、
有効値の69.9%は**西側**（沖積低地）。→ 液状化の判定対象になっていない地盤として扱う。

**-1.0 と -6.6 の違いは分からないので区別せず「判定対象外」とまとめる。**
「判定対象外」と「危険度なし（PL=0）」は画面で必ず分ける。市に確認が取れたら直す。

## MCP同梱

`kjishin_mcp.py`（3ツール）。Claude Code / Codex / Claude Desktop から住所判定を呼べる。

```
claude mcp add kjishin -- /path/to/kjishin/.venv/bin/python /path/to/kjishin/kjishin_mcp.py
```

- `kjishin_check` 住所・地番・座標から震度と液状化
- `kjishin_parcel` 地番から筆の位置と範囲
- `kjishin_status` 収録件数・データ時点・出典

読むだけで書き込む口は無い。**判定は製品本体の関数をそのまま呼ぶ**ので画面と食い違わない。
notes（予測であって確定ではない等）を必ず一緒に返し、AIが数字だけ抜いて断言しないようにしている。

## 動かす

```
.venv/bin/python scripts/load_nagoya.py   # 震度・液状化
.venv/bin/python scripts/load_chiban.py   # 地番参考図（約4分・DBは /mnt/data に置いてsymlink）
systemctl --user enable --now kjishin.service
bash scripts/deploy_proxy.sh
```

PostGISもDockerも要らない。メッシュは矩形なので SQLite の R*Tree だけで 0.2ms。

## 正直に書いていること

- **予測**であって、実際にこの震度になると決まっているわけではない
- 地番参考図は名古屋市が「**求積および権利関係等の確認の根拠となるものではない**」と明記
