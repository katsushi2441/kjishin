# kjishin をこれから触るAIへ

FastAPI ＋ SQLite(R*Tree) ＋ shapely ＋ pyproj。データは名古屋市オープンデータ（CC BY 4.0）。

## 先に読むもの
- `README.md` の「設計の芯」。とくに「区域外」「判定対象外」「範囲外」の3つの区別。
- `app/codes.py` の冒頭コメント。**PL値の負の値をどう扱うか**の根拠が書いてある。

## やりがちな誤り
- **液状化の負のPL値を「液状化しない」と訳す。** 違う。**判定の対象に入っていない**。
  -1.0 と -6.6 の2種類あるが**定義が公開されていない**ので、区別せず「判定対象外」とまとめる。
  分布を実測して台地（市東部）に偏ることを確認済み。推測で別々の意味を付けない。
- **地番参考図の座標系を緯度経度だと思う。** `.prj` が入っていない。中身は
  **平面直角座標系（メートル）第VII系（EPSG:6675）**。取り込み時に EPSG:6668 へ変換する。
  第6系だと京都、第8系だと静岡に飛ぶので、おかしいと思ったらまず座標を1点変換して確かめる。
- **地番参考図を求積や権利の根拠に使う。** 名古屋市が「根拠となるものではない」と明記している。
- **PostGIS を持ち込む。** メッシュは矩形なので R*Tree で 0.2ms。要らない。
- **市外を「液状化なし」と答える。** 対象は名古屋市内のみ。市外は status='outside'。

## データ更新
名古屋市の配布は年1回。BODIK のデータセットから最新のZIPのURLを取り直し、
`scripts/load_nagoya.py` の SOURCES と VINTAGE、`scripts/load_chiban.py` の ZIPS と VINTAGE を更新する。
取り込み後は **PL値の負の値の種類**（今は -1.0 と -6.6 の2つ）が増えていないか必ず確認する。
増えていたら、また分布を実測してから扱いを決める。

## MCP
`kjishin_mcp.py`。製品本体の関数をそのまま呼ぶ薄い橋にしてある。**ここで別の判定を作らない。**
notes を必ず返すのは、AIが数字だけ抜いて「震度6強です」と断言しないようにするため。
